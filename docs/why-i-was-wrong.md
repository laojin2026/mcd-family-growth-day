# 我用麦当劳 MCP 做了一个「带娃吃麦当劳」的工具，然后发现自己的算法是错的

> 项目地址：https://github.com/laojin2026/mcd-family-growth-day
>
> 麦当劳程序员节创意开发大赛参赛作品。第一次做 GitHub 项目，欢迎拍砖。

---

## 一、先说结论

这个项目做出来之后，我推翻了自己一开始的算法。

我原本想当然地认为：**给孩子选餐，选蛋白质最高的就行**。

结果一拉麦当劳官方的真实营养数据，发现**儿童餐的钠含量差异接近一倍**：

| 餐品 | 蛋白质 | 钠 |
|---|---|---|
| 儿童鱼排堡 | 15 g | **442 mg** |
| 麦麦趣鸡球 | 19 g | **789 mg** |

麦麦趣鸡球蛋白更高（19g vs 15g），但钠也高 79%。

对一个 8 岁孩子来说，**「蛋白最高的那份」恰恰是钠负担最重的那份**。如果我按原来的思路推荐，家长会拿到一份「看起来很健康」但钠超标的双倍餐。

所以我改了算法，改成三重约束：

```
1. 先卡年龄段能量区间（6 岁/8 岁/11 岁/13 岁+ 各有不同）
2. 再按蛋白质排序（候选集内择优）
3. 钠超限的直接淘汰（不因为蛋白高而豁免）
```

改完之后实测：8 岁儿童 + 1 成人，全餐 1115 kcal、蛋白 59 g、儿童能量占比 38%。

**这个修正过程，我完整写在了 `MCP_INTEGRATION.md` 第 0 节。**

## 二、我为什么做这个

先坦白一件事：**我看到前 100 名里全是省钱券、卡路里、优惠券**，教育类只有一个中文课 Skill，亲子类是 0。

但我自己带娃去麦当劳，最难受的从来不是「怎么省钱」。

是这些：

- **点单环节**：顺着孩子点（薯条、可乐、甜筒），回来血糖一波动就闹脾气；按大人需求点，孩子全程没参与感；想折中，就开始拉扯。
- **吃饭环节**：大人刷手机，孩子闷头吃，一整顿饭零交流。
- **开口环节**：一句「你怎么又不听话」，在餐厅这种高压场景里，只会升级成对抗。

**这不是营养问题，是关系问题。**

而关系，正好是我做了 5 年的老本行（家庭教育/亲子沟通）。所以我想试试：**能不能用官方 MCP 数据 + 亲子沟通方法论，把一顿饭拆成三件事**。

## 三、它到底能干什么

### 1. 吃什么 —— 有数据依据的均衡配餐

调用 `list-nutrition-foods` 拿官方餐品营养成分（能量、蛋白质、脂肪、碳水、钠、钙），
调用 `query-meals` / `query-meal-detail` 拿当前门店真实在售。

然后按上面的三重约束，为「1 大人 + 1 儿童」组合出套餐。

### 2. 怎么说 —— 能直接照读的话术

基于亲子沟通四步法：**描述事实 → 表达感受 → 说明影响 → 给选择**。

不是通用鸡汤，是针对此刻场景的具体句子。比如：

| 场景 | 生成的话术 |
|---|---|
| 孩子只想要甜品 | 「你今天想吃甜甜的，麦麦的冰淇淋确实很诱人。我们先吃正餐，正餐吃完就带你去拿 —— 好不好？」 |
| 吃饭要手机 | 「我看到你一直想拿手机。这顿饭我们不看屏幕。吃完这 15 分钟我陪你玩猜拳。」 |
| 点单意见分歧 | 「你想要巨无霸套餐，妈妈想要麦麦鸡腿堡。今天我们一人一份自己的，然后分享一半，好吗？」 |

### 3. 留什么 —— 成长仪式

每次用餐后生成一个轻量成长记号（今日成长关键词 + 父母观察日记 + 下一个待解锁仪式）。

**但这里有个我很在意的设计**：生成仪式前，**必先调用 `campaign-calendar` 查官方正在进行的亲子活动**，有官方活动就优先推荐官方活动，**不自己编**。

实测发现麦当劳官方正在做「乐享 90 分钟高质量亲子时间」（9 本热门书籍每月更新 + 开心乐园餐 + 随机玩具）、「趣读派对」、「过家家派对」。

**一个有官方活动时优先引导去官方活动的工具，和一个自己编活动的工具，是两个物种。**

## 四、它不是截图演示

这是我最想强调的一点。

`scripts/mcd.py` 是一个**零第三方依赖**的 MCP 客户端 + 配比算法实现，只用 Python 标准库。

```bash
git clone https://github.com/laojin2026/mcd-family-growth-day.git
cd mcd-family-growth-day
export MCD_MCP_TOKEN="你的Token"

python scripts/mcd.py check                       # 连通性 + Token 状态
python scripts/mcd.py tools                       # 列出 35 个 MCP 工具
python scripts/mcd.py plan --age 8 --adults 1     # 跑出完整配餐方案
python scripts/mcd.py call query-nearby-stores --args '{"latitude":31.23,"longitude":121.47}'
```

**任何人、任何时间、任何环境下，都能复现 README 里的每一个数字。**

## 六、踩的坑（也许对你有用）

**1. 空仓库第一次传文件，不能直接用 Git Trees API**
会报 `409 Git Repository is empty`。正确姿势：先用 Contents API `PUT` 任意文件生成 main 分支 → `DELETE` 掉 → 再 Trees API（`base_tree=base_sha`）+ Commits + `PATCH refs`。

**2. fine-grained PAT 有两个独立的坑**
- 不勾 `Repository access` → 403 `This token does not have access to any repositories`
- 不加 `Contents: Read and write` → 403 `Resource not accessible by personal access token`
（改完权限，旧 Token 依然有效，不用重新生成）

**3. GitHub 设备码（device flow）拿到的 Token 是个陷阱**
它返回 `ghu_` 前缀，是 GitHub App 类型，`X-OAuth-Scopes` 为空，**根本不能建仓/写文件/发 Issue**。别在这上面浪费时间。

**4. 网页发 Issue 报 `Unable to create issue`**
是 CSRF token 失效（多半是代理缓存了页面）。强制刷新或关代理解决。

**5. 代理**
本机代理对 `github.com` 间歇性 CONNECT 502（10 秒超时），但 `api.github.com` 稳定 0.3 秒。**能走 API 就别走网页。**

**6. `curl -d` 的 `%20` 不会解码**
`scope=public_repo%20read:user` 会把 scope 原样传过去，GitHub 收不到任何权限。用 `+` 或 `--data-urlencode`。
